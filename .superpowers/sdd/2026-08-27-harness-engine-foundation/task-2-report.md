## Public API summary

- `PlanStatus = 'Todo' | 'InProgress' | 'InReview' | 'Blocked' | 'Done'`.
- `transitionPlanStatus(plan, nextStatus, completionEvidence?)` returns a new immutable plan row and validates completion preconditions.
- `WorkflowSnapshot` carries schema version, revision, workflow identity, plan rows, optional integration merge lease, and optional read-time `updatedAt`.
- `ArtifactStore` exposes `readWorkflow(workflowId)` and optimistic-concurrency `writeWorkflow(expectedRevision, next)`.
- `JsonArtifactStore` is the first concrete store and uses only filesystem JSON operations.

## Concerns

- The JSON store intentionally supports only schema version 1 and rejects future versions rather than migrating them.
- `updatedAt` is generated by the store on every write and is optional only when constructing an in-memory snapshot.
- Same-workflow writes use an exclusive same-directory lock file. Locks are always cleaned up by a completed writer; unknown leftover locks are rejected rather than auto-expired, avoiding removal of a potentially active writer's lock.
- Lease objects remain extensible for coordination metadata, while known lease fields (`leaseId`, `holder`, `acquiredAt`, `expiresAt`) are type-checked and runtime prompt/transcript/credential/tool-payload/dynamic-task fields are filtered from serialized JSON.
