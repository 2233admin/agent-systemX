# 测试计划

## 验证范围与层级

| 层级 | 目标 | 工具/入口 | 通过标准 |
|---|---|---|---|
| OpenSpec 合同 | 验证 coverage change 工件、来源合同和 `skip_specs` | `npx openspec validate bmad-openspec-coverage --strict` | change valid |
| live spec 回归 | 确认覆盖整理没有修改当前长期规范 | `npx openspec validate --specs --strict` | 三份 live spec 全部通过 |
| 来源覆盖 | 确认 BMad 主要来源、live specs、入口和 archive 均有映射 | 人工逐条核对 05 矩阵及来源路径 | 每条记录 source、target、status、evidence、action |
| 冲突诚实性 | 确认冲突和未知没有被静默归一化 | 人工审阅 03/04/05 | conflict/partial/unknown 有明确说明，不自动升格 |
| 权威边界 | 确认矩阵不是第三套产品真源 | 文件范围检查 | 不修改 live specs、BMad、archive 或产品源码 |
| 回滚边界 | 确认移除 coverage change 不影响源材料 | `git status --short` 与路径检查 | 新增内容限于本 change；runtime 依赖保持既有 gitlink |

## 自动化资产

```text
06-测试方案/
├── fixtures/
├── scenarios/
├── runtime/
└── runner/*.ts
```

本轮不新增 fixture、runner 或运行态脚本。覆盖关系主要依赖可回读 Markdown、OpenSpec strict validator 和人工语义审阅；不能用关键词命中替代正文阅读。

## 失败与停止条件

- 任一来源路径无法回读时，相关关系标记 `unknown`，不继续归类为 covered。
- 发现矩阵复制了私人原文、凭据、prompt、transcript 或运行态时停止。
- 发现矩阵新增无来源 Requirement、自动改写 live spec 或 BMad 原文时停止。
- 发现 BMad `done` 被当作 OpenSpec `verified`，停止并修正状态分层。
- strict validation 或 runtime guard 失败时停止，不进入 acceptance。
- 发现需要删除、重命名、归档源材料时停止，另开明确授权的迁移 change。

## 数据准备与清理

- 使用仓库现有公开路径，不复制源文件正文进入 fixture。
- 不创建 SQLite、客户端进程、网络发布物或用户个人状态。
- 每次实际审查使用独立 `runs/<run-id>/`，保留输入、输出、trace 和清理记录。
- 本 change 不执行源材料迁移；无动态资源需要清理。

## 07 任务生成输入
